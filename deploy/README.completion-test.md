```powershell

```

The creator selects tracked Git blobs, installs locked public dependencies with offline npm ci / ignore-scripts, and builds a fresh VITE_CRM_TEST frontend in staging. It does not copy ignored node_modules or private environment files. A cache miss is a preparation failure, not permission for silent network/copy fallback. The runtime projection omits only dotenv's README.md and README-es.md distribution documentation: their published placeholder private-key examples trigger the unchanged secret scan. Locked dependency metadata, runtime code and license remain included; other files retain the same scan. Final packages are new `releases/crm-test-<full-commit>` directories; existing destinations are not overwritten. Every payload/dependency file has a size and SHA256 in `release-manifest.json`, with source Git blob hashes and build/lock metadata. The package hash is the SHA256 of this manifest; no ZIP archive is claimed. Files become read-only. Administrator modification is still possible, so startup and new-package child recovery recheck the pinned inventory rather than treating a directory name as proof.

Use the owned TEST transition helper with the same private startup config:

It validates the canonical task/owner/Node, current CRM process chain and native identity, saves the previous config reference, stops only that TEST watchdog/supervisor/CRM children, and archives only the supervisor identity record. It atomically selects the package and starts the same scheduled task, waiting for the new owned chain and unchanged native PID/creation identity. Journal, AI policy, native identity and DB records are not reverted. Normal readiness failure attempts the previous validated config; a changed config or foreign process requires operator inspection. Timestamp/code/phase metadata stays outside Git. This helper does not perform LIVE deployment, DB restore or native-service restart.

Actual A→B→A→B evidence, package hashes, external ERP release references and normal CRM use belong in CRM_STATUS.md and the outside-Git acceptance log.
